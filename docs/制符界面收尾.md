# UI-4 制符界面收尾

2026-10-16，炼器阁·界面接入。依据 `design/12_制符一期.md` 第二节、`art/icons/ui/talisman/talisman_ui.json` 与稳定接口文档，将制符窗接为一期正式界面。`data/features.json` 中 `talismanCraft`、`lifeSkillCurve` 继续默认关闭。

## JSON 排版区域

窗口采用 JSON 的 640×400 坐标，窗体、标题、内框和关闭图标复用炼丹窗口资源；主按钮复用炼丹按钮，放弃/继续使用 `abandonOrContinueImage` 的次级对话选项图。

| JSON 区域 | 界面内容与数据来源 |
|---|---|
| `recipeList.row/rowGap/rowImages/rowSlices` | 四种符卡，按当前选择、未学或许可不足切换卡面；产物图标与名称来自配方。未学通过 `knownRecipes` 区分，其余锁定原因读取正式 `check` 和只读生活技能许可。缺料不把符卡画成未学。 |
| `recipeList.inkTab` | 独立研墨按钮，采用指定坐标、切片与炼丹按钮图，文案为 `talisman.ink_tab`。 |
| `sectInfo` | 读取 `view.sectBonus/qualityCap` 显示宗门成功率加成与最终品质上限。 |
| `detail.output` | 所选配方的产物图标、符名；有正式结果时使用 `view.result` 的物品、品质、数量。 |
| `detail.materials` | 从 `view.check.materials` 显示持有/所需，采用 ok/lack 槽图；图标放槽内 +4,+4，缺料叉在 +33.5,+33.5、缩放 0.6。来源说明沿用 `talisman.paper_source/ink_source/material_lack`。 |
| `detail.preview` | 显示配方产出数、`view.rate`、规则 `qualityMin` 和开始扣料提示；不从界面完成度反算品质或自行掷骰。 |
| `detail.paper` | 选符预览用独立符纸；正式绘制改用 trial 累计帧，中心与缩放读取 `fxCenter/fxScale`。 |
| `detail.sequence` | 配方完整方向序列，绘制时仅高亮 `view.draw.current`；箭头和键帽由程序绘制。 |
| `detail.stepBar` | 正式模式显示 `view.draw.remainingMs / recipe.draw.stepTimeMs`，暂停时跟随系统冻结；填充先三切至满宽，再用遮罩裁剪剩余比例，保留端帽。 |
| `detail.strokeFeedback` | 根据 `view.draw.lastOutcome` 显示正确/错误/超时图标和对应文案；进度、正确数与完成度只读 `view.draw`。 |
| `quality` | 成功结果使用最终品质签；不提前展示随机或尚未确定的成符品质。 |
| `detail.buttons` | 开始/再来、放弃/继续、关闭按钮；启用状态读取 `view.buttons`，绘制期间关闭先进入放弃确认。 |

## 状态与结算边界

`TalismanScene.refresh` 获取完整 `TalismanSystem.view(selected)`，连同只读 `qualityMin`、生活技能视图和界面确认状态交给 `TalismanPanel.setState`。Panel 负责按 JSON 展示与资源回退，仅向 `select(id)` 或 `action('start'|'again'|'abandon'|'continue'|'close')` 发意图。

开始、研墨、方向输入、逐帧超时、暂停/恢复、放弃与再制继续调用正式系统接口。本次不改 `TalismanSystem` 的扣料、结算、存档事务、发奖或经验逻辑；材料余额不从背包另算，成功率不在 UI 中叠加宗门或等级项。

有结果时只展示当前配方对应的 `view.result`；成功显示最终品质、符名、实际数量，失败区分 `completion/condense/interrupted`。`pendingOutput` 显示 `talisman.output_pending` 并阻止再次制作。领取仍由 Scene `update` 中的 `claimPending()` 自动重试，结果按钮不直接领取或发奖。

放弃确认属于界面状态 `confirming`。点击放弃或绘制中关闭时先 `pauseFor('confirm')`，确认后才调用 `abandon()`；继续时只移除确认暂停原因，其余失焦、场景或全局暂停仍然有效。失焦恢复时清除界面残留方向和按下沿，并忽略系统按键连发，避免后台松键事件丢失后卡在等待状态。恢复后沿用系统的等待方向键松开规则，地图、物理和人物输入隔离方式不变；再次开窗优先保留系统上次所选配方。

## 画符帧与资源回退

绘制开始隐藏独立 `ui_talisman_paper`，正确数为 0 时用 `fx_trial_talisman` 的 blank 帧，每次正确后按累计正确数切到 `stroke_0c`。错误和超时只叠 `fx_talisman_draw` 的 miss/timeout，不清空累计帧。成功使用 done；凝符失败播放 craft_fail 前隐藏独立符纸和 trial sprite，避免双纸或旧笔画叠放。

静图、物品图标和特效按件检查可用性；缺件采用程序槽框、纸面、箭头、反馈和品质文字回退。继续使用 optional load，素材缺失不阻断面板或发出浏览器错误。布局 JSON 也按可选资源加载；缺失时使用 Panel 内与当前美术表一致的默认布局，不因缓存缺项而无法开窗，正常情况下仍优先采用 JSON 坐标。

## 生活技能等级只读展示

Scene 只调用 `Progress.lifeSkillView('talisman')`，不读取或写入经验曲线表。仅当返回的 `enabled && available` 为真时，在 `sectInfo` 附近显示等级与经验条；关闭开关时不显示，满级按 `maxed` 处理，不用 0 经验需求作除数。

**制符等级条专用坐标待美术补 JSON。** 当前以宗门信息附近可用区域安排展示，参考炼丹等级条的字号与条形样式；不向 balance 表增加字段，不自行制造等级或经验需求。正式成功率仍直接使用 `view.rate`，不会因显示等级再次加成。
