# 性能 P1 接入

对应负责人诊断 `reports/负责人/20261015_卡死与性能诊断.md` §6 P1-1、P1-2 与 F1。

启动前由 `src/rendererChoice.ts` 在临时 WebGL context 读取
`WEBGL_debug_renderer_info.UNMASKED_RENDERER_WEBGL`，识别 SwiftShader、llvmpipe、
Software、Basic Render、Microsoft Basic 等软件渲染名称，自动选择 Canvas。
临时 context 用完即释放；无 WebGL、扩展不可用或探测抛错时回到 Phaser.AUTO。
正式入口与测试桥共用选择/信息函数，不改 crashGuard 与 resetRunState。

URL 参数可与原有参数叠加，例如 `?map=bamboo_forest&reset=1&renderer=canvas`：

- `renderer=auto`：默认值，探测后决定；未知值也按 auto 处理。
- `renderer=canvas`：强制 Canvas。
- `renderer=webgl`：强制 WebGL，便于人工对照。

F1 继续同时开关物理调试与原 debugText；叠加层显示实际渲染器 WebGL/Canvas、
`game.loop.actualFps` 与可用的 GL 短名。名称最多 72 字符，完整名称留在测试快照中。
Canvas 自动回退时保留启动探测的 GL 名，方便定位软件渲染。

可选图片、精灵表、图集按纹理缓存跳过，普通 JSON（含 `*_anims`）按 JSON 缓存跳过；
缓存键沿用 Loader 的 prefix。图集命中仍返回“资源可用”，可单独补载缺失的动画 JSON。
技能、道具及丹炉炉火图集也按纹理缓存跳过，避免 atlas JSON 不进 JSON cache 导致重复请求。
无需新增 BootScene；纹理被主动移除后，下次 preload 仍可正常重新加载。

验证命令：

```sh
npm run sync
npx tsc --noEmit
npm run build:test
npm run test:optional-assets
npm run test:smoke:perf-assets
npm run test:smoke:perf-renderer
npm run build
```

两个新冒烟默认先 build:test 再启动本地 preview；也可设 `XT_SMOKE_BASE_URL` 复用测试服务。
浏览器沿用 freeze 冒烟的 Chromium 探测，支持 `PLAYWRIGHT_MODULE`、`CHROMIUM_EXECUTABLE_PATH`。
素材冒烟在首屏完成后至少换图两次，检查新增 sprites JSON、技能/道具图集 JSON 与全部 art
素材请求为 0，主循环仍推进。
渲染器冒烟覆盖软件名称判定/探测失败、URL 覆盖、F1 真实按键与数字 FPS；只读快照
`window.__xt.rendererSnapshot()` 仅存在于 `VITE_XT_TEST=1` 测试桥，正式构建无此探针。

已知限制：GPU 信息受浏览器隐私策略与驱动影响；无法取得名称时沿用 Phaser.AUTO，
用户可用 URL 强制 Canvas。强制 WebGL 在无 WebGL 的浏览器上可能启动失败。
无头 SwiftShader 的 FPS 不代表硬件加速真机表现，本次不设 FPS 性能门限，亦未做全量资产预算优化。
`talismanCraft`、`lifeSkillCurve` 默认继续为 false。
