## 读取字段与行为

- 职位表读取 `version/enabled`、`rules.{rankOrder,initialRank,v05MaxRank,contributionBasis,promotionSpendsContribution,demoteOnSpend}`、`ranks[].{id,name,nameKey,icon,availableInV05,reqContribution,reqRealm,balanceTodo,promotion.mode,promotion.dialogueKeys,unlocks.libraryTier,unlocks.shopShelf}` 和 `sects[].{id,name,promotionNpc,stewardNpc,titles}`。晋升只升相邻档，验当前贡献和境界，内门确认、亲传接受誓问，不扣贡献，消费不降职。称号与徽记只作身份展示。
- 正式拜宗沿原任务/职业接口授外门；职位开关不影响入宗。存档 `sectRank` 未入宗为 null；旧档缺字段时只由正式职业或已交付拜宗事实补外门。已有未知或身份矛盾记录完整保留并暂停宗门服务；后续档位保留，本期权限封顶亲传。
- NPC 读取 `services[].{type,sect,config}`，按 `sect_promotion→sect_ranks`、`sect_shop/sect_library→shops`、`sect_donation→sect_donations` 白名单分派，核对正式本宗身份及登记长老/接引人。未知配置、异宗、旧青云接引人均不能绕过准入。服务菜单保留日常、普通任务和原对白，复用现有分页/数字菜单；上交只增加预览和确认入口。
- 货架保持 `shops[npcId]` 数组，读取两类商品。字符串是普通商店货品，按 `items.price` 单件扣灵石，贡献不变；旧代码仅登记字符串货架而没有购买菜单，本次补 `ordinaryCatalog/buyOrdinary` 与最小菜单，沿用原货架、排序和售价。对象 `{item,reqRank,costContribution,enabled}` 只扣贡献，绝不叠加或回退灵石价；可选 `balanceTodo` 缺失视为无待填，若存在则须为空数组。关闭商品不上架、直接购买也拒绝；未知物品/职位、非法或 null 价格、待填、未来/关闭物品均拒绝。职位按 `rankOrder` 与解锁货架/目录判定，高档包含低档，职位不足显示中文门槛。
- 秘籍保留物品 `sect/reqLevel/unlockSkill` 和原功法学习条件，只交付书，不自动学习；已学功法不可重复兑换。五宗同档高阶书目齐备才开放。上交每日额度不会变成商店限购，独立新确认可再次购买。
- 上交读取 `sect_donations.{version,enabled,offers[]}` 与每条 `id/sect/npc/item/reqRank/enabled/count/rewards.sectContribution/dailyLimit/balanceTodo`。总表及条目双开关、职位配置和消费者均须就绪；批数、贡献与上限须为正安全整数、待填为空。只接受本 NPC 的永久材料白名单，排除临时试炼物、装备中物品、不可用物品及所有贡献货品（即使货品尚未启用），防止回流。
- 每次上交一整批，确认时重新核对身份、职位、永久库存和配额。按运行端本地 05:00 日界、每存档每 offerId 分别计数，不积攒离线额度。预览返回当日剩余批数并展示 `sect.donation.quest_warning/remaining`；跨日旧预览返回 `sect.donation.day_changed`，重新打开预览再确认。跨日预览不写状态，新确认成功时才原子重置当日批数，保留贡献及历史收据。上交与日常分别扣材料，不占日常条数，不调用日常发奖，不加灵石、经验或好感；同份材料不能交给两套系统。
- `Progress.permanentCount` 校验永久量，临时与永久同 id 时只扣永久库存，临时量仍由原试炼接口清除。`sectGrowthState` 保存 `donationDay/donationBatches/settledTransactions`；旧档只补缺失的合法容器，异常记录保留并暂停交易。收据 `{kind,sect,sourceId,day}` 的来源分别为上交 id、`npcId|itemId`、目标职位。独立确认新建事务 id，同笔重试复用原 id；刷新、重复回调、跨日重试已成功事务均不重复结算。
- 晋升、贡献商品、普通商品和上交均在一次 `Progress.save()` 中保存成果及收据；上交同时保存扣料、贡献、批数和新日界。失败完整恢复内存余额、库存、职位及业务状态，不写成功收据、不播成功；不串调会自行保存的 gain/spend 接口。背包没有槽位上限，沿用数量字典并校验安全整数，不虚构容量。日常、闭关维持既有接口及各自日界。
