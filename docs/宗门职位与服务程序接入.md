# 宗门职位与服务程序接入（v0.5）

依据根目录 `design/13_宗门成长.md`、`design/01_配置表规范.md` G15 和既有 `docs/宗门日常程序接入.md`。dev 读取共享配置；本次只提交代码、测试与文档，未刷新 `data/`、未改配表、未执行 snapshot，也不推送。这里只记录开发自测，验收归执法堂。

## 读取字段与行为

- 职位表读取 `version/enabled`、`rules.{rankOrder,initialRank,v05MaxRank,contributionBasis,promotionSpendsContribution,demoteOnSpend}`、`ranks[].{id,name,nameKey,icon,availableInV05,reqContribution,reqRealm,balanceTodo,promotion.mode,promotion.dialogueKeys,unlocks.libraryTier,unlocks.shopShelf}` 和 `sects[].{id,name,promotionNpc,stewardNpc,titles}`。晋升使用当前贡献余额和 `realms.json` 的境界顺序，只升相邻档；内门确认，亲传须接受誓问。晋升不扣贡献，消费不降职；只授职位称号和目录/货架权限，没有属性奖励，也不重复发入门奖励。
- 正式拜宗沿原任务/职业接口授外门，开关关闭不影响入宗。存档新增 `sectRank`，未入宗为 null；旧档仅缺字段时根据正式职业或已交付拜宗任务补外门，不从贡献、五宗帖、试炼选择或地图推算。已有未知、身份矛盾的职位记录保留并暂停新服务；后续档位保留，本期目录权限封顶亲传。
- NPC 读取 `services[].{type,sect,config}`，按 `sect_promotion→sect_ranks`、`sect_shop/sect_library→shops` 白名单匹配正式本宗身份与登记 NPC。服务菜单保留日常、普通任务和原对白；长目录分页，数字键每页最多五项。上交材料和差遣不在本次实现范围。
- 商品读取 `shops[npcId][].{item,reqRank,costContribution,enabled,balanceTodo}`，依职位表顺序与解锁货架/目录检查；高档包含低档。未知物品/职位、价格 null/非法、待填或未启用均不扣款。旧字符串货架仍保留灵石语义，不转换为贡献商品，不回退 `items.price`。读取物品 `id/name/type/sect/reqLevel/unlockSkill`；秘籍只交付物品，已学功法不可重复兑换，后续学习仍沿原条件。高阶书目须五宗同档配齐才启用。
- 称号从宗门和职位推导，HUD 显示完整称号一次，余额复用 `sect.ui.contribution`。徽记读 `icon_sect_rank_<rankId>`；sync 仅登记已转正的同名图片，缺图显示文字，`art/icons/_pending/sect_rank_v05/` 不加载、不转正。
- 晋升和交易使用 `sectGrowthState.settledTransactions` 保存确认事务收据（`kind/sect/sourceId/day`）；同一确认重试复用 id，新兑换另建 id。扣款、交货或职位更新与收据同次保存，失败恢复原内存状态，不播成功。`Progress.save()` 现在返回保存结果；新交易没有串调会各自保存的 gain/spend 接口。日常与闭关沿原接口和原日界。

## 当前配置与缺口

本次读取的共享 `sect_ranks.json` 五档 `balanceTodo` 已清空：外门 0/炼气、内门 500/筑基、亲传 1400/金丹；执事 4000/金丹、长老 10000/金丹仍为后续档。**总开关 `enabled:false`**，正式晋升继续显示 `sect.ui.config_pending`，不由程序自行开启。

`shops.json` 目前仅有王婶、孙郎中的旧字符串货架，缺五宗接引人和长老的贡献商品。设计中的 15 件补给、1 件秘籍都仍是草案，其 16 项 `costContribution` 尚未落表；因此正式商店和藏经阁显示筹备，禁止交易。四宗高阶秘籍内容也尚未齐备，草案 `protect_charm` 不在当前合并物品表。程序不会补价格、免费发货或猜替代 id。

现有背包是物品数量字典，未登记槽位容量；本次检查接收数量合法且不溢出安全整数，并处理交货失败回滚，不虚构容量数值。四宗山门地图与长老点位仍缺；保留日常已有的本宗接引人兼容入口，不另造长老点位。所用 `sect.*` 文案齐备，没有新增硬编码对白；职位、称号、晋升、筹备、锁档、确认、余额不足、存档失败与交易回执均读取现有 key。
