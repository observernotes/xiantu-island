# 神识逻辑接口（v0.5b P0）

本次接入提供扫描、保存、目标适配、平台本体渲染及事件。窗口、HUD、按钮、按键绑定和扫描／显形高亮特效由界面层接入。正式功能默认关闭；`features.spiritScan`、`sense.json.enabled`、合法数值与运行接口均就绪后，筑基及以上角色才能施放。目前正式地图没有 `hidden` 点位，怪物没有 `sense` 登记。测试夹具仅存在测试构建的浏览器内存。

权威规则：[14_神识.md](../../../design/14_神识.md)、[01_配置表规范.md G16](../../../design/01_配置表规范.md#g16-v05-神识)。

## GameScene 的接口

场景创建完毕后访问 `scene.sense`。核心类型见 [Sense.ts](../src/Sense.ts)。不应通过改写 `Progress` 字段绕过接口发起扫描。

| 调用 | 返回及用途 |
| --- | --- |
| `preview()` | 当前预览，不扣费、不写盘；确认施放时会复检 |
| `requestScan(source, scanId?)` | 同步返回 `SenseScanResult`，`source` 只接受 `'key'` 或 `'button'` |
| `monsterIntel(monsterInstance)` | 传当前真实 Monster 实例；返回临时白名单快照，缺失时为 `undefined` |
| `intelList()` | 当前场景仍有效的情报数组；同时清理到期／死亡记录 |
| `revealedHidden(mapId)` | 此静态地图已经显形的 `hidden` 对象名数组 |
| `markTutorialSeen()` | 教学确实展示后调用；保存成功才返回 `true`，已经展示过也返回 `true` |
| `tick()` | 清理到期／死亡／离图情报；GameScene 每次更新已调用 |
| `clearIntel()` | 清空临时情报；场景关闭及读档已调用 |
| `registerAdapter(kind, adapter)` | 注册所属系统适配器，返回注销函数；`kind` 为 `'encounter'` 或 `'secret_chest'` |

`preview()` 返回：

```ts
{
  strength?: number, radius?: number, mpCost?: number, cooldownMs?: number,
  cooldownRemainingMs: number,
  ready: boolean, blockKey?: SenseBlockKey, unlocked: boolean,
  sources: readonly unknown[], diagnostics: string[]
}
```

`strength` 只读当前有效 `Progress.stat('spirit')`，`radius` 保留完整精度。非法或未填数值不提供可用数值；`diagnostics` 仅供诊断，不应在玩家界面展示内部字段名。`sources` 目前提供角色加点与已生效心法的中文来源条目；未来补充来源仍应以原属性系统计算值为准，不在扫描中再次加成。

一般拒绝顺序为境界、功能就绪、存活、忙碌、冷却、灵力；功能总开关关闭时，`requestScan` 始终返回 `sense.block.unavailable`。界面使用 `blockKey` 对应的 `sense.*` 文案，不自行推算优先级。对话、演出、换图、生活技能、打坐闭关和模态窗口应阻止施放，移动／跳跃／普通战斗不阻止。新交互可通过 `scene.registerSenseBusy(() => boolean)` 注册忙碌判断，返回函数用于注销。

成功结果包含：

```ts
{
  ok: true, scanId: string, replayed: boolean,
  instanceId?: string, center?: { x: number, y: number },
  radius?: number, strength?: number,
  result: 'found' | 'known' | 'faint' | 'empty',
  resultKey: 'sense.result.found' | 'sense.result.known' |
             'sense.result.faint' | 'sense.result.empty',
  count: number, faint: boolean,
  hits: Array<{
    kind: 'chest' | 'platform' | 'entrance' | 'monster_info',
    id: string, x: number, y: number, newlyRevealed: boolean
  }>
}
```

失败结果为 `{ ok: false, blockKey, scanId? }`，不扣费。`save_failed` 也不会显示成功。`count` 仅计首次显形物件及平台，怪物与已知物件不计数。`faint` 表示本次范围内存在合法但强度不足的目标，可在 `found`／`known` 反馈外追加模糊异息文案；这些目标不会进入 `hits`，不能给出名称、位置、方向或阈值。

中心、半径和地图实例在本次操作开始时冻结，含圆形距离边界，不看朝向和地形遮挡。空扫同样扣费、进入真实时间冷却并保存；冷却中重按立即拒绝，不排队。键盘与按钮调用同一方法。输入层应在一次按下沿只发一次请求，并在重试时沿用同一个 `scanId`；已经成功的同标识重试返回 `replayed: true`，不重复扣费或发布成功事件。若重试来自读档后的最近成功标识，可返回无位置／命中详情的 `known` 确认结果。不要把长按的每帧输入构造成新的扫描意图。

## 场景事件

通过 `scene.events.on(...)` 订阅，在界面销毁时注销。事件载荷为可序列化数据，不携带 Phaser 对象。

| 事件 | 载荷和时机 |
| --- | --- |
| `'sense:scan'` | 成功持久提交后恰好一次；载荷为成功结果加 `source`、`highlightMs`，包含冻结的 `center`、`radius`、`instanceId` 与 `hits` |
| `'sense:intel-expired'` | 情报因到期、死亡、销毁、离图或读档被清理；`{ instanceId, id }` |
| `'sense:blocked'` | 请求被拒绝时；`{ ok: false, blockKey, scanId?, source }` |

界面收到 `sense:scan` 后可按冻结中心与逻辑半径播放 `fx_spirit_scan_wave`，对首次显形命中播放 reveal。`highlightMs` 只控制表现持续时间，不能用于撤销显形或平台碰撞。界面关闭或特效失败不退费、不重提扫描。仅正在查看的情报失效时显示 `sense.monster.expired`。

```ts
const onScan = (result: SenseScanSuccess & { highlightMs: number }) => {
  // 按 result.center / radius 播放表现；按 hits 更新标签。
};
scene.events.on('sense:scan', onScan);
const preview = scene.sense.preview();
const result = scene.sense.requestScan('button', currentInputOperationId);
// 教学实际展示完成后：scene.sense.markTutorialSeen();
```

本层没有注册默认快捷键；界面层从输入动作 `spirit_scan` 的真实绑定生成 `{key}`，未绑定使用 `sense.ui.no_binding`，不要占用 B／K／Q 或技能快捷栏。

## 情报与保存

`MonsterIntel` 固定包含 `instanceId`、`id`、`scannedAt`、`expiresAt` 和 `titleKey`。`name`、`level`、`hp`／`maxHp`、`abilities` 只有在怪物 `sense.visibleInfo` 白名单中才存在；`hp` 是成功提交时快照。未授权姓名时 `titleKey` 为 `sense.ui.inspect`，不可向 `{monster}` 注入定义名或怪物 id。允许能力但公开列表为空时，`abilities` 使用 `sense.monster.unknown` 文案。复扫覆盖快照和到期时间，不累加时长；不写图鉴、不改击杀、不提供弱点增伤。

有记录且开关开启时，Progress 保存 `senseState: { cooldownUntil?, lastScanId?, tutorialSeen }`；没有历史的旧档不补字段。损坏时间戳保留诊断并暂停施放。权限从当前成功达到的境界派生，不保存 `senseUnlocked`。冷却使用 `Date.now()`，游戏时间加速不加速冷却；离线只经过冷却，不补扫。

静态地图生命周期明确为 `mapId` 即实例，浏览器刷新不产生新实例。显形由 Progress 的地图对象状态 `senseRevealed` 按 `mapId|objectName` 保存。`hidden` 宝箱／非奇遇入口绑定原生对象：未显形时不显示、不可交互；显形后仍须原生主动交互。平台显形后只开启上表面单向落脚，读取存档时先恢复碰撞再创建玩家，不因高亮结束或神识降低撤销。

## 隐藏平台本体

平台未显形时不创建本体渲染对象；扫描持久提交后的 `applyReveal()` 同步开启单向碰撞并创建本体。重进场景／读档时，在创建 `Player` 前同步恢复已显形平台的碰撞和画面。显形不会自动移动玩家；`highlightMs` 到期、冷却到期或神识降低均不移除本体或碰撞。功能关态不渲染隐藏平台。

本体复用当前地图已加载的 tileset 和 MapBuilder 的 `=` 单向平台规则：左端／中段／右端／单格依次为 tile 8／9／10／11，位置变体和不可用变体的回退也沿用同一规则。青云村使用 `tiles_qingyun`。地砖按 32×32 横向平铺，非整格宽度将末格横向缩放到剩余宽度；视觉上沿为 `object.y`，左右为 `object.x` 与 `object.x + object.w`，深度与普通单向平台相同（`-1`）。本体 `alpha=0.85`，保留清楚可辨的落脚上沿，碰撞仍为完整的上表面单向碰撞。

未加载地砖或 `useTiles=false` 时，使用 MapBuilder 同样的色块回退：土黄色主体 `0xc9a56b` 高 14px，绿色上沿 `0x6fd25a` 高 `SPEC.oneWayEdge`。扫描波纹、`fx_spirit_scan_reveal`、额外外描边与呼吸高亮仍由界面层按 `sense:scan` 事件接入。

当前素材只有扫描波纹与显形特效，没有专用显形平台本体；现用地图单向地砖已提供可见落脚面，不阻塞本体接入。本次不新增或覆盖任何 art 文件，也不改 `art/polished.lock` 中的精修图。

| 建议文件名 | 尺寸 | 用途与交付要求 |
| --- | --- | --- |
| `art/tiles/tiles_sense_platform.png`（配同名 `.json`） | 128×32 RGBA，4 格各 32×32 | 左端／中段／右端／单格四种平台本体；首行像素即落脚上沿，不留透明顶边，主体可半透明，上沿须清楚；中段左右无缝平铺，端头可裁切／缩放以适配非整格宽度。无需九切，不烘焙 reveal 光晕或呼吸动画；若改交九切，须另外标注固定端宽和可横向平铺的中心区。 |

## 后续所属系统适配

奇遇运行时与随机秘境隐藏箱目前未实现，不注册适配器，不加入候选或奇遇池，不伪造 `enc_hidden_abode` 的抽取／seen／attempt 或秘境奖励账本。

`registerAdapter('encounter' | 'secret_chest', { targets(context) })` 提供接口。适配器只返回当前实例已激活的合法 `SenseTarget`，显形状态仍归所属系统，需设置 `persistence: 'adapter'`、`revealed()` 与 `stageReveal()`；`stageReveal()` 暂存本次状态并返回撤销函数，扫描保存失败时调用撤销。`applyReveal()` 用于保存成功后的实际可见／碰撞应用。奇遇适配器须验证当前 visit 已选中事件、有效 attempt、原 req、trigger.anchor 与本对象一致，以及 hidden.reqSpirit 和事件阈值相等；同次保存写当前 attempt 的入口显形和 seen，主动交互才启动对白，不写 resolved 或奖励。秘境保留 G13 原生 `chest.hidden` 语义与 run／room 对象账本；清房前尚未生成的箱子不入候选，旧箱缺 reqSpirit 表示无额外强度门槛，显式 null 则不可用。

`future.weakness` 没有执行路径。本期保留文案和接口边界，不应用任何伤害倍率。

## 测试构建入口

`VITE_XT_TEST=1` 的 `XtTestBridge` 暴露以下 `window.__xt` 方法，正式构建不包含测试桥：

- `sensePreview()`、`senseScan(source, scanId?)`、`senseIntelList()`、`senseMonsterIntel()`。
- `senseFixture({ enabled?, cooldownMs?, inspectDurationMs? })`：内存启用表／模板，向当前 Tiled 图内存副本注入 hidden 平台、宝箱控制对象和原生宝箱，真实重建场景并生成带 `sense` 块的测试怪物。
- `senseSpawnMonster()`、`senseHitMonster(damage)`、`senseFixtureSnapshot()`：真实怪物受击、死亡和碰撞／保存的浏览器断言辅助。
- 现有 `__xt.events` 可订阅或 drain 三种 `sense:*` 事件；用 `__xt.setFlag('spiritScan', true)` 单独打开功能开关。

`npm run test:sense` 覆盖纯逻辑与两种 `XT_DATA`。先 `npm run build:test`，再运行 `npm run test:smoke:sense` 验证真实 Phaser 场景中的扣蓝／冷却、隐藏交互、平台本体／碰撞对齐与读档恢复、怪物快照和生命周期，以及默认关态不写神识记录或渲染平台。显形前后截图保存到 `SENSE_SHOT_DIR`（默认 `dist/sense-shots/`）。测试不会改写 balance JSON、正式地图或 monsters.json。
