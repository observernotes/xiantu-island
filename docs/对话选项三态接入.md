# UI-2 对话选项三态接入

`DialogBox.choosePage` 使用正式 HUD 图 `ui_hud_dialog_option_selected`、`ui_hud_dialog_option_normal`、`ui_hud_dialog_option_disabled`。旧 borrowed 记录 `ui_hud_dialog_option` 保留原样，业务选项仍由调用方提供，`DialogChoice` 的 label/onSelect/disabled?/reason?/rankIcon? 接口不变。

## 布局与切片

- 保留对白框上方纵排、按钮宽 592、行距 6。每行按 label/reason 换行和 rankIcon 计算高度，至少达到素材表高度（正式图 28），保留原来无徽记 30、有徽记 36 的最低行高。
- 按钮容器坐标是左上角；三态底板在容器内 `(0, 0)` 拉伸到按钮宽高。使用 `sliced`，九切片边距完全由 `hudSpec` 读取 `hud_ui.json` 的 `nineSlice` / `slice`；WebGL 使用 NineSlice，Canvas 沿公共 helper 整图拉伸。
- 文字读取当前状态的 `text.size/color/x`，正式配置为 14px，normal/selected `#3B2A20`、disabled `#8E867C`，x 缩进 12。文字垂直居中，rankIcon 占用原有 32px 缩进，禁用徽记维持 0.6 透明度。
- 可用项光标使用 `ui_hud_cursor`，原点读取 `hudSpec.origin`。光标相对按钮为 `(-14, height / 2)`，即世界/父容器坐标 `x = btn.x - 14`、y 为按钮中心。光标不做呼吸动画。

## 状态与键位

- 每页默认首个可用项选中；鼠标悬停把焦点移到该项，移出后保留焦点。选中项显示 selected 和金色 ▶，其他可用项显示 normal；disabled 没有交互区域和光标。
- 数字键 1–5 仍直接调用 `selectChoice(index)`，不会改为确认焦点；禁用项继续在 `selectChoice` 拦截。Esc 沿现有入口关闭选项菜单。
- 最多五项直接展示；超过五项沿用每页三项业务选项，加前页/后页按钮。翻页重新选中首个可用项。对白推进、NPC/宗门/试炼业务回调均不改。
- 关闭、替换对白、翻页均销毁选项容器及其子件并清空焦点，不保留上页对象。

## 可选资源与回退

先 `npm run sync`，四件 PNG 由现有递归同步进入 `public/art/icons/ui/hud/`，并登记在 `src/gen/assets.json.uiImages`。public 与 src/gen 是仓库现有的忽略生成目录，无需提交副本。

`preloadHud` 将四件独立交给 `loadOptionalImage`。清单外不入队、不探测；清单存在而 PNG 实体缺失时，沿现有可选资源错误处理静默失败，调用方按纹理是否存在回退。HUD 其他硬加载项不变。

回退按件、按状态进行：仅缺 normal/selected/disabled 中一张时，仅使用该状态的底板退回原 rectangle；其余状态仍用图。矩形保留原填色、边框和字色（可用 INK，禁用 INK_60），selected 矩形使用原悬停填色。缺 cursor 时用代码文字金色 ▶。光标缺失不影响底板，底板缺失不影响光标。按钮保留 `state` / `artUsed` data，底板和光标也标记 `artUsed: art|code` 便于复核。

## 自测入口

```sh
npm run sync
npx tsc --noEmit
npm run build
npm run test:optional-assets
npm run test:smoke:dialog-ui
```

smoke 创建独立快照工程、测试构建和 preview，不覆盖工作树正式 dist，也不改共享数据/素材。默认截图和 JSON 结果在 `/workspace/reports/ui2/`，可用 `XT_DIALOG_UI_SHOTS` 覆盖。浏览器依赖沿现有 smoke 查找 Playwright/Chromium，也支持 `PLAYWRIGHT_MODULE` 和 `CHROMIUM_EXECUTABLE_PATH`。

测试使用仅在 `VITE_XT_TEST=1` 加载的 `__xt.openDialogChoices(choices, rankIcon?)` 展示夹具，输入为不带 onSelect 的选项；实际调用真实 `dialog.choose`，回调展示该项 label。GameScene 无新增测试分支。正式构建运行原 leak-check，排除测试接口。

覆盖正常三态 NineSlice/文本/布局/光标、rankIcon、真实鼠标和数字键、禁用/全禁用、分页与焦点清理；还会在浏览器内存中替换 `slice` 数组与文本配置验证读表。缺图覆盖四件从清单一起移除（无请求），以及逐个移走临时 dist 的 PNG（清单仍在，preview 返回 200 HTML，解码失败）。每个浏览器上下文断言原始 console.error/pageerror/requestfailed/HTTP 错误全部为零；实体 PNG 用 finally 还原。

## 是否需要主程序补逻辑

本次验收不依赖主程序新增逻辑：现有 `choose`、`selectChoice`、分页、禁用字段和 rankIcon 已足够。

现有 GameScene 没有“上下键移动选项焦点、确认键提交焦点”的分发：↑ 在对白中仍调用 `advance()`，有选项时被原逻辑忽略。若后续要求完整键盘焦点操作，需要主程序确定上下键/确认键的规则，并提供受 modal 限制的按键分发与焦点移动/确认入口；数字键直选语义应继续保留。本次只实现默认焦点与鼠标悬停，没有扩展该玩法输入约定，也没有联系其他 bot。
