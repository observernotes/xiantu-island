# 《仙途岛》配置表规范 v0.1

> 主策划：天机阁 ｜ 供 演武堂（填表）与 炼器阁（读取）对齐字段。所有表为 UTF-8 JSON，放 `/workspace/xiantu/balance/`，地图放 `/workspace/xiantu/maps/`。
> 通用约定：`id` 用小写蛇形英文（如 `spirit_rabbit`），显示名用 `name` 中文字段；时间单位毫秒，距离单位像素（地块 32px），概率用 0–1 小数。

## 1. realms.json 境界表
```json
[{ "id": "qi_refining", "name": "炼气期", "levelMin": 10, "levelMax": 29,
   "stages": ["初期","中期","后期","圆满"], "breakthroughItem": "foundation_pill",
   "breakthroughQuest": null, "failPenalty": { "expLossRatio": 0.1, "debuffMs": 600000 } }]
```

## 2. exp_curve.json 经验曲线
```json
{ "maxLevel": 29, "expToNext": { "1": 15, "2": 34 } }
```
`expToNext[n]` = 从 n 级升到 n+1 级所需修为；境界圆满级的值即突破所需修为。

## 3. player_growth.json 角色属性
```json
{ "base": { "hp": 50, "mp": 10, "atk": 5, "def": 0, "speed": 100, "jump": 100 },
  "perLevel": { "hp": 12, "mp": 4, "statPoints": 5 },
  "statEffects": { "rootBone": { "hp": 2, "def": 0.5 }, "agility": { "hit": 0.5, "evade": 0.3 },
                   "spirit": { "mp": 3, "matk": 1 }, "insight": { "expBonus": 0.002 } } }
```
属性键：`rootBone` 根骨、`agility` 身法、`spirit` 神识、`insight` 悟性。

## 4. monsters.json 怪物
```json
[{ "id": "spirit_rabbit", "name": "灵兔", "level": 1, "hp": 20, "atk": 4, "def": 0,
   "exp": 3, "aggressive": false, "moveSpeed": 40, "patrolRange": 160,
   "touchDamage": true, "knockback": 120, "respawnMs": 7000,
   "sprite": "mon_spirit_rabbit", "dropTable": "drop_rabbit", "isBoss": false }]
```

## 5. drops.json 掉落
```json
{ "drop_rabbit": { "spiritStone": [1, 5], "items": [ { "item": "rabbit_fur", "chance": 0.4, "count": [1,1] } ] } }
```

## 6. skills.json 功法
```json
[{ "id": "sword_qi_slash", "name": "剑气斩", "sect": "tianjian", "type": "active",
   "mpCost": 6, "cooldownMs": 0, "damageRatio": 1.6, "hitCount": 1, "maxTargets": 1,
   "range": { "w": 280, "h": 48 }, "maxLevel": 20, "perLevel": { "damageRatio": 0.05 },
   "fx": "fx_sword_qi", "key": "default:A" }]
```
`type`：`active` 术法 / `passive` 心法。

## 7. items.json 物品与装备
```json
[{ "id": "wood_sword", "name": "桃木剑", "type": "equip", "slot": "weapon",
   "reqLevel": 1, "stats": { "atk": 8 }, "price": 50, "icon": "icon_wood_sword", "stack": 1 },
 { "id": "qi_pill", "name": "回气丹", "type": "consume", "effect": { "mp": 50 }, "price": 20, "stack": 100 }]
```
`slot`：`weapon` / `robe` / `shoes`（demo 只用这 3 格）。

## 8. npcs.json / quests.json
```json
[{ "id": "village_elder", "name": "李村长", "map": "qingyun_village", "x": 640, "sprite": "npc_elder",
   "dialog": ["孩子，你身上……竟有灵根？"], "quests": ["q_awaken"] }]
```
```json
[{ "id": "q_awaken", "name": "觉醒灵根", "giver": "village_elder", "reqLevel": 1,
   "objectives": [ { "type": "kill", "target": "spirit_rabbit", "count": 5 } ],
   "rewards": { "exp": 30, "spiritStone": 50, "items": [] }, "next": "q_bamboo" }]
```
`objectives.type`：`kill` / `collect` / `talk` / `reach`。

## 9. 地图（maps/*.json）
推荐用 Tiled 导出 JSON，图块 32×32。图层约定：
- `bg_far` / `bg_mid` / `bg_near`：视差背景（图像层）
- `ground`：实心地块；`oneway`：单向平台（顶部 8px 碰撞）
- 对象层 `objects`：`rope`（x, y, height）、`ladder`、`portal`（`target` 地图 id + `targetPortal`）、`spawn`（`monster` id + `count`）、`npc`（npc id）、`playerStart`

## 附录 v0.2 修订（2026-10-09，回复演武堂 02_数值说明 第 6 节）

### A. 攻防成长（确认）
`player_growth.json` 的 `perLevel` 增加 `atk`、`def`；`statEffects.rootBone` 增加 `atk`。演武堂给的 `perLevel.atk 1.5`、`perLevel.def 0.5`、`rootBone.atk 0.4` 照用。设计意图：剑修主属性是根骨，根骨同时给气血、防御和少量攻击；武器仍是攻击的主要来源（占比建议 ≥ 60%），免得加点比换装备更值。

### B. 怪物可选字段（补入规范）
| 字段 | 类型 | 说明 |
|---|---|---|
| `aggroRange` | 像素 | 主动怪进入仇恨的水平距离；缺省时被动怪受击才仇恨 |
| `attack` | 对象 | 普通怪的单个主动攻击：`type`（`slam` 等）、`damageRatio`、`range{w,h}`、`cooldownMs`、`knockback` |
| `skills` | 数组 | 首领技能。通用字段 `id` `name` `type` `cooldownMs` `damageRatio`；`projectile` 加 `count` `speed`；`dash` 加 `distance` `telegraphMs`；`summon` 加 `summon`（怪物 id）`count` `hpBelow` `once`，以及 `grantRewards`（默认 false：召唤物不给修为、不掉落、不计任务击杀和图鉴击杀数）和 `despawnWithOwner`（默认 true：首领死亡时召唤物播消散特效后一起移除）。首领技能另有可选字段 `interruptible`（默认 false）：前摇（`telegraphMs`）期间受击照常扣血、出受击闪白，但不打断出招、不被击退、不重置冷却 |

`training_dummy` 木人桩：`exp: 0`、无 `dropTable`、`moveSpeed: 0`，另加 `noDamage: true`（不碰撞伤害），`respawnMs` 设 0 表示不死（气血归零即回满）。

### C. 新增 id 登记
物品与 NPC 的 id、显示名、类型已登记进 `balance/items.json` 和 `balance/npcs.json`，数值字段（`stats`、`effect`、`price`、`reqLevel`）由演武堂填写。

### D. 任务字段补充（v0.2）
- 新增 `turnIn`（交付 NPC，缺省同 `giver`）、`objectives[].map`、`collect` 目标的 `consume`（交付时扣除）。
- 新增目标类型 `breakthrough`（`realm` 为目标境界 id）：要求当前等级修为圆满，交付时触发突破演出。
- `rewards.job`：完成后转职的职业 id（demo 只有 `tianjian_disciple` 剑徒）。

### E. 地图 zone 对象（v0.2，演武堂提出，确认）
- `zone`（矩形）：`unlockQuest` 接取该任务后才刷首领；`bossOnly` 区内只刷首领。
- 首领登场台词（02_新手任务.md 任务 5「首领登场」）在玩家首次进入该 zone 且首领已刷出时触发一次。

### F. 第三阶段登记（v0.3，回复演武堂 03_数值填表 第六节）
- **物品**：新丹药 `clear_mind_pill` `sword_intent_pill` `foundation_pill` `golden_core_pill`，以及占位的 `nascent_pill`（realms.json 金丹突破已经引用）、残页 `scroll_ten_thousand_swords`（`type: skill_scroll`、`unlockSkill`）、丹炉 `bronze_furnace` `purple_copper_furnace` `dark_iron_furnace`（`type: tool`、`toolType: furnace`），已进 `items.json`。
- **材料**：留在 `materials.json`，与 items.json 同结构，程序启动时合并成一张物品表。

## 附录 G：v0.4 定稿（2026-10-09）
> 以下以 `balance/` 里现有文件为准反推定稿；程序按这里接，字段有变动先改这里再改表。

### G1. 文件总表
| 文件 | 顶层结构 | 说明 |
|---|---|---|
| `items.json` + `materials.json` | 数组 | 启动时合并成一张物品表，id 不得重复。**物品的唯一来源**；`recipes.json` 的 `newItems` 只是演武堂的备注，程序不读 |
| `skills.json` | `{ rules, skills[] }` | `rules`：`spPerLevel` `jobAdvanceBonusSp` `masteryCapBonus` `budget`（只供参考） |
| `recipes.json` | `{ rules, recipes[] }` | 见 G3 |
| `enhance.json` | 对象 | 见 G4 |
| `breakthrough.json` | 对象 | 通用突破规则：`overflowPoolRatio` `pillQualityBonus{low,mid,high,supreme}` `insightBonusPerPoint` `insightBonusCap` `clearMindPillBonus` `pityPerFail` `maxRate` |
| `realms.json` | 数组 | 新增 `trial` `baseRate` `failPenalty` `reward`；瓶颈等级 = 每个境界的 `levelMax` |
| `trials.json` | 数组 | 新增 `waves` `objective`；`balanceNote` 仅备注 |
| `quests.json` | 数组 | 见 G2 |
| `strings_zh.json` | 对象（key→文本） | `_meta` 跳过；占位符 `{x}` |

### G2. 任务（quests.json）完整字段
- 顶层：`id` `name` `giver` `turnIn` `reqLevel` `objectives[]` `rewards` `next` `phase`（第几阶段启用，程序只加载 `phase` 不大于当前版本阶段的任务；缺省为当前）`note`（备注，不读）。
- `objectives[].type`：
  | type | 字段 | 完成条件 |
  |---|---|---|
  | `kill` | `target` 怪物 id、`count` | 接任务后击杀计数 |
  | `collect` | `target` 物品 id、`count`、`consume` | 背包持有数 ≥ count；交付时 `consume` 为 true 就扣除 |
  | `talk` | `target` NPC id | 和该 NPC 对话一次 |
  | `reach` | `target` 地图对象名、`map` | 进入该对象范围 |
  | `breakthrough` | `realm` | 当前等级修为圆满（交付时触发突破） |
  | `craft` | `target` 产出物品 id、`count` | 接任务后通过丹炉（以后包括炼器、制符）成功产出的数量 |
- `rewards`：`exp` `spiritStone` `items[{item,count}]` `skills[{id,level}]` `recipes[]`（丹方 id，学会即解锁）`job` `unlockTrial`。

### G3. 丹方（recipes.json）
- `recipes[]`：`id` `name` `output` `outputCount` `recipeLevel` `baseRate` `materials[{item,count}]` `fuelStones` `realm` `price`（商店售价）`reqLevel`（购买等级）。
- `rules`：公式说明 `formula` 仅备注；程序用 `perAlchemyLevel` `levelGapPenalty` `minRate` `maxRate` `furnace{id:加成}` `fire{skipped,inZone,perfect,missed}` `quality` `alchemyExp`。

### G4. 炼器（enhance.json）
- `levels[]`：`to`（目标等级）`rate` `stones` `refineStones` `dropOnFail`（失败掉几级）。
- `statPerLevel{weapon,armor}`、`milestoneBonus{"7","10","12"}`、`protectCharm`、`forge{grade,affixCount,forgingLevelShift}`、`enchant{elementDamage,sameRootBonus,cost}`、`salvage{refineStonesByGrade}`。v0.4 不做炼器，先不接。

### G5. 技能（skills.json `skills[]`）
`id` `name` `sect` `job` `type`（`active` / `buff` / `passive`）`maxLevel` `spCost` `masteryPerHit` `masteryToCap` `mpCost` `cooldownMs` `damageRatio` `hitCount` `maxTargets` `range{w,h,behind?}` `durationMs` `perLevel{字段:每级增量}` `effects` `req{技能id:等级}` `fx` `icon` `key`。
行为补充（霸体、后摇取消等）见 `05_剑徒一转技能.md`，暂不进表，以后有第二个技能需要再加 `effects` 子字段。

### G6. 首领技能特效命名（确认丹青阁假设）
`monsters.json` 的 `skills[]` 不单独写 `fx` 字段，特效键约定为 `fx_<怪物短名>_<技能id>`，预警特效再加 `_warn` 后缀，例如 `fx_fox_phantom_dash_warn`。确实需要例外时，再给这个技能写一个 `fx` 字段覆盖。首领技能数以配置表为准。

### G7. 传送门 / zone 的 `unlockQuest` 语义（澄清）
- **传送门**的 `unlockQuest`：该任务**已完成**才能通行；没完成时提示 `sys.portal_locked`。旧字段 `locked: 1` 保留，表示永久关闭。
- **zone**（首领区）的 `unlockQuest`：该任务**已接取且未完成**时才刷首领（打首领本身就是任务目标）。
- 两处语义不同，程序请分开实现。
