# UI-4 制符完整玩法接入

依据 `design/12_制符一期.md`、`balance/09_制符数值.md`。本次只实现玩法、状态接口及既有 UI-4 按钮接线，不修改共享或快照数值表、美术、五宗试炼脚本。

## 开关与入口

`src/features.ts` 的 `talismanCraft` 控制整个功能，`data/features.json` 显式为 `false`。关闭时不增加墨符使对话项，不启用品质符箓使用、快捷栏或增益效果，不给旧档补写空的制符新字段；已经存在的制符存档数据保留。炼丹仍使用 `alchemyPhase1` 与原有丹炉、燃料、经验、火候和随机品质规则。

开启后，`lingfu_envoy` 的对话挂载「学习制符」「制符」，表中尚缺 `talisman_craft` 服务时按 NPC id 提供兼容入口。`q_talisman_intro` 按表检查等级、境界；接取前的对话不算教学，交付只授予一次 `rewards.recipes` 中的五个配方。授方仍通过 `Progress.grantQuestRecipes`，与炼丹共用去重记录 `learnedRecipes`。

实际地图入口沿用现成山门地图与墨符使点位。开关开启时仅注册现有 `lingfu_pavilion` 单图及 `MAP_AREA`，船老大已有航线可自然抵达；未新增其它山门，不修改地图或配表文件。

## 界面稳定接口

| 接口 | 输入与返回 | 接入用途 |
|---|---|---|
| `GameScene.talismanView(recipeId?)` | 返回当前视图，开关关闭返回 `null` | 界面层读取正式玩法状态的场景入口 |
| `GameScene.openTalisman(recipeId?)` | 返回是否成功开窗 | 正式入口；检查场景、战斗、试炼和互斥面板后启动独立 `TalismanScene` |
| `TalismanSystem.view(recipeId?)` | `TalismanView` | 一次取得配方、当前选择、材料预检、成功率、宗门加成/品质上限、按钮状态、尝试、绘制进度、结果、待领取及配置错误 |
| `TalismanSystem.check(recipeId)` | `{ok, reason?, materials:[{item,have,need}]}` | 开始/研墨按钮状态和阻止原因；`reason` 包含关闭、忙、未学、等级、境界、状态、缺料、背包、待领取和配置错误 |
| `start(recipeId, now)` / `grind(recipeId?)` | 预检结果，成功附尝试/结果 | 开始正式付料画符，或一次研墨；数量始终读取 `outputCount` |
| `input(down, now, frame?)` / `advance(now, frame?)` | 结算时返回 `TalismanResult`，否则 `null` | 每帧提供当前按住的方向集合、事件时间和递增帧号；无人输入时仍推进超时 |
| `pause(now?)` / `resume(now?)` | 无返回值 | 失焦或确认弹层暂停玩法时钟，恢复后等待方向松开 |
| `abandon()` / `again(now)` / `close(confirmAbandon?)` | 放弃/关闭是否成功，或新一轮预检结果 | 放弃不会返料；再制重新预检并生成独立尝试；关闭时活动尝试须先明确确认放弃 |
| `recover()` / `claimPending()` | 返回是否实际改变状态 | 中断恢复和自动领取；结果面板、关闭按钮不得直接发奖 |
| `TalismanScene.select(id)` / `action(action)` | 配方选择与按钮意图 | `TalismanPanel` 回调只发 `start/again/abandon/continue/close`，由场景处理确认和状态同步 |
| `GameScene.useTalisman(itemId, quality)` | `{ok,key?,params?,casting?}` | 使用指定品质堆；失败通过 `t(key, params)` 显示原因 |
| `Progress.qualityCounts/countQuality/removeQuality/addCraftedItem` | 品质数量/原子前的背包操作 | 背包按 `(itemId,quality)` 展示，商店/任务仍用 `count(itemId)` 汇总 |
| `Progress.bindTalismanSlot(index,item,quality)` | 存档成功与否 | 快捷栏固定品质，耗尽不换用品质；传 `null` 解绑 |

`view.draw` 含 `mode/strokes/current/total/correct/wrong/timeouts/completion/remainingMs/waitingRelease/paused/done/lastOutcome/redraws`。`current` 是从零开始的当前笔索引；完成度保持原始分数，不以界面百分比反推结算。`view.buttons` 为 `start/grind/again/abandon/close/continue` 的可用状态；放弃确认弹层由界面管理。

`view.result` 保存 `attemptId/recipeId/item/success/quality/rawQuality/capApplied/count/completion/correct/wrong/timeouts/total/rate/roll/reason/delivered`。`reason` 区分完成度不足、凝符失败及中断；受宗门上限影响时显示最终品质并提示 `capApplied`。`pendingOutput` 表示结果已确定但尚未入包。

`TalismanScene` 暂停地图、物理和人物输入，以既有 `TalismanPanel.setState` 驱动按钮及信息；不重新制作美术。界面层可以直接消费上述稳定视图替换当前信息排版。`XtTestBridge` 的开窗、按钮、快照、用符等接口只在 `VITE_XT_TEST=1` 构建的动态分支加载；正式构建不暴露 `window.__xt`。

## 状态机与结算一致性

```text
select ──开始且预检通过/扣料并保存──> drawing
 drawing ──完成画符/保存确定结果──> settled
 drawing ──确认放弃或重新读档─────> interrupted
 settled ──入包失败──────────────> pending（结果不重掷）
 pending ──容量恢复/实际入包─────> settled（delivered=true）
 settled/interrupted ──再制且预检通过──> 新 attemptId 的 drawing
```

`DrawStroke` 是不依赖 Phaser 的共用判定器，`mode='craft'` 时只认新的按下沿，同帧多方向只使当前笔出错一次；按错、超时都推进，截止时刻输入按超时。低于完成度门槛不调用随机源；达标后只取一次随机数，用 `roll < rate`，品质由未舍入完成度决定并按已拜入宗门封顶。非法配置禁用对应配方并提供错误清单，不补默认成功率。

开始前检查材料和最大产出容量。当前背包没有格数上限，沿用物品计数并检查计数有效性/溢出。开始扣料和 `drawing` 记录在同一 `runSaveTransaction` 提交；结算、品质入包或 `pendingOutput`、任务事件进度也在同一事务保存。写盘失败回滚全部持久字段，确定后的结果保留供重试，不二次掷骰。

同一尝试只结算一次；只有正式成功且实际入包才向 `QuestSystem.onCraft(item,count)` 发一次实际数量。研墨同样通过正式制作入包路径记录实际 `outputCount`。试炼组件不发 `craft`，没有真实材料/品质/产物。

`DrawStroke('trial', sequence, 0)` 提供无本笔时限、错笔清当前道并保留原序列的策略。既有 `SectTrial` 的 #12 画符及第三道完成后靶场启动流程继续使用原实现，未为本次正式制符改写，不将画符完成直接视作整个试炼完成。

## 持久化与旧档

- `Progress.talisman`：`version:1`，`nextAttempt`，`attempt{attemptId,recipeId,state,result,craftEmitted}`，`pendingOutput`。读档 `drawing` 变 `interrupted`，不退料；已结算/待领取只恢复不重新制作。
- `learnedRecipes`：继续存所有配方 id，任务奖励去重；不另造与任务脱节的已学标记。
- `pillQualities`：沿用炼丹品质账本键，扩展到所有 `qualityEnabled` 物品；`inventory[itemId]` 保留总数量。开启功能后的旧品质物品未分桶余量归 `low`；普通材料数量原样保留，反复读档不会重复补入。
- `Progress.talismanUse`：`version:1`，`buffs[{buffId,itemId,quality,实际强度,expireAt}]`，`cooldowns{cooldownGroup:expireAt}`。四档品质共用物品配置的冷却组；有效到期时刻在切图/读档后继续使用，过期或非法条目才清理。未知非 1 版本原样保留并拒绝用符，避免新存档被旧程序降版覆盖。
- `visitedMaps`：持久记录真实到访的已注册地图。旧档仅能从已存位置补当前地图，无法证明的历史到访不猜测；首次实际到访村镇后才可作为遁地候选。
- `talismanQuickSlots`：保存快捷槽的 `{item,quality}`，指定品质耗尽时拒绝使用，不自动消耗其它堆。

功能关闭时不执行新迁移或效果，旧丹药迁移保留原行为；关闭再开启不会清除已有的有效制符增益/冷却/结果。所有现实时间使用 `gameNow()`，正式环境动态读取 `Date.now()`，测试构建可注入时间源；画符场景暂停不会延长增益或冷却。

## 四符效果与场景回调

`new TalismanUseSystem(prog,host,{items?,now?,enabled?})` 的 `precheck/use/update/interrupt/onDeath/cast` 是纯逻辑接口；`configErrors` 列出失效物品字段。`use/effect/byQuality` 全部读取物品表，每档合并后重新校验全部行为字段、四档齐全及单调性。主配置或覆盖非法即禁用该物品，不给数值兜底。

| 行为 | 场景接线与提交点 |
|---|---|
| 火符 | `host.emitProjectile(effect)` 向面朝方向生成弹体。生成成立就扣指定品质和灵力、启动冷却，打空仍成功；首敌命中走原伤害、防御、受击、死亡、任务和掉落路径，碰地形/越射程销毁 |
| 护身 | 实际减伤比例和上限保存到增益；`Progress.damageFrom` 在防御后乘 `talismanDamageMultiplier`，和其它百分比相乘后按配置上限封顶，最终统一取整。固定/剧情扣血不走此函数；死亡由 `onDeath` 清除护身 |
| 聚灵 | `Progress.gainExp(...,'kill')` 把 `talismanGatherBonus` 与悟性加成相加后计算一次；任务显式 `source='quest'`，闭关、制作及溢出返还不加。死亡不清聚灵，到原现实时间到期 |
| 遁地 | `use` 只建立临时 `cast`，不扣料/CD；`update` 到时再次预检、复核锁定目标及落点，`host.teleport` 成立才同次提交。移动、攻击、实际受伤、死亡、切图调用 `interrupt`；读档不恢复未完成读条，也没有预扣需要返还 |

同类护身/聚灵按品质比较，拒绝低品质覆盖；同品质刷新完整时长，高品质替换，均只保留一层；两类增益可同时存在。`host.emitProjectile/teleport` 可以返回回滚回调，写盘失败时销毁弹体/撤销待执行迁移，避免效果和消耗分离。

`nearestTalismanTown(currentMap,{level,quests,visitedMaps,edgeOpen?},maps?)` 按可通行传送门和已解锁飞舟边做 BFS，选择最少换图次数的已到访村镇，并列按地图 id 排序；永久锁、等级/任务锁、未来阶段及试炼专用边不通行。`reachableTalismanTown` 只复核开始读条时锁定的目标。候选须有合法 `playerStart`，不以 `safeZone` 替代村镇；试炼、封闭首领战、禁止回城图、已在村镇和无候选全部拒绝，不扣消耗。

- `npcs.json`：`lingfu_envoy.services[]` 缺 `type: talisman_craft` 服务；程序按该 NPC id 挂载学习/制符入口，保留原宗门服务和任务，不改原表。当前服务表使用对象形式，登记时沿用既有结构。
- `lingfu_envoy.shop: true` 及对应符纸货架尚未登记，是设计中的可选墨符使售纸入口；当前闭环使用已登记的 `shops.json.grocer_wang` 符纸和 `recipe_spirit_ink` 研墨，不影响制符材料来源。
- `q_talisman_intro` 的等级/境界、五个配方奖励、墨符使任务挂载当前均已登记；无需程序补造任务奖励数值。

## 山门单图注册与关闭回退

`lingfu_pavilion.json` 在共享目录和快照中均已存在，已有墨符使、长老和返回落霞镇的飞舟。`syncTalismanMapAvailability()` 在 `GameScene.create` 开始和 `applyFeatureFlags` 时同步运行注册表：开启 `talismanCraft` 时仅把这一张现成地图加入 `TILED_MAPS` 和 `MAP_AREA`，关闭时撤下。船老大已有的山门航线直接抵达原地图和原 NPC，无需新增地图点位或调整其它宗门开放阶段。

`trial_lingfu_range` 的旧 #12 试炼入口 NPC 和回程继续保留，单图注册不会撤下既有 foyer、替代画符/靶场流程或重复启动计时。关闭开关时，已在山门的角色安全迁到落霞镇 `playerStart`，不恢复气血/灵力、不执行死亡或复活结算；尚在试炼的返回位置也从山门迁到该落霞落点。读入包含山门位置的存档时应用同样回退，避免关开关后被无效地图困住。

山门注册和自然入口现已由程序补齐，不再列为缺配表项；仍待地图负责人登记的是上节明确列出的村镇/回城布尔属性。
