# 商店逻辑接入（backlog #9）

本次补齐逻辑层与最简调用入口，商店窗口归界面接入 UI-5。普通 NPC 沿用 `NPCS[npcId].shop` 与 `balance/shops.json` 的 NPC 货架登记，王婶、孙郎中等入口复用现有对白选项，购买、出售均单件确认。

## 配置与货币

- `shops[npcId]` 的字符串是普通商品 ID，读取物品表 `item.price` 作为灵石购买单价；普通购买不扣宗门贡献。
- 普通回收读取永久背包中可用、非占位且有有效价格的物品，不限于 NPC 正在售卖的货品。回收单价为 `Math.floor(item.price / 2)`；没有价格、价格非法或取整后为零的物品不进入出售目录。
- 临时试炼物品不计入可出售量。装备槽与背包分开：可出售同 ID 的背包备用装备，装备槽保持原样；只有装备槽中物品而无永久背包库存时不可出售。
- G15 对象 `{ item, reqRank, costContribution, enabled }` 沿用宗门贡献兑换，只扣贡献，按本宗正式身份、职位与货架权限校验，不叠加或回退到灵石价。`enabled:false` 的对象不显示，直接兑换也拒绝；现有宗门商品配置仍保持关闭。

## 逻辑接口

接口位于 `src/SectGrowth.ts`，配置副本沿用 `SECT_GROWTH_CONFIG`，货品来自 `balance/shops.json`，交易读写当前 `Progress`。

| API | 返回与调用约定 |
| --- | --- |
| `ordinaryCatalog(npcId)` | `{ ok, key, entries }`；每项含 `itemId/name/price/ok/key`，`price` 为单件灵石购买价。 |
| `buyOrdinary(npcId, itemId, transactionId, count = 1)` | 购买指定正整数数量，确认时重验货架、价款、库存接收条件与功能开关。 |
| `ordinarySellCatalog(npcId)` | `{ ok, key, entries }`；每项含 `itemId/name/price/count/ok/key`，`price` 为单件回收价，`count` 为可出售的永久库存量。 |
| `sellOrdinary(npcId, itemId, transactionId, count = 1)` | 出售指定正整数数量，确认时重验永久库存、回收价、灵石加款安全范围与功能开关。 |
| `catalog(npcId, 'sect_shop' \| 'sect_library')` | 宗门对象货架预览，返回职位、贡献价格和准入结果。 |
| `exchange(npcId, 'sect_shop' \| 'sect_library', itemId, transactionId)` | 沿用贡献兑换事务，单次交付一件。 |

目录只读；失败不扣钱、不扣物、不产生成功收据。成功交易将余额、背包与收据在同一次保存中写入；保存失败恢复内存状态。每次独立确认生成新 `transactionId`，同次回调重试复用原 ID，成功收据随存档保留以阻止重复结算。买入、卖出和数量作为不同交易来源校验，不能借旧 ID 执行另一笔交易。

## 功能开关与最简入口

`data/features.json` 新增 `shops:false`，默认关闭。普通购买、出售的目录与结算均受 `shops` 控制，关闭时 NPC 不提供普通商店选项；已打开的旧确认也无法结算。宗门商店 `sect_shop` 须同时开启 `shops` 与 `sectShopLibrary`；藏经阁 `sect_library` 保持原来的 `sectShopLibrary` 开关规则。

`GameScene.openOrdinaryShop(npcId, mode = 'buy')` 保留旧购买调用，并可传 `'sell'` 打开回收目录。对白选项以 `ui.shop.buy/ui.shop.sell` 切换；购买沿用 `ui.shop.menu/confirm/complete`，出售使用 `ui.shop.sell_confirm/sell_complete`，空出售目录使用 `ui.shop.empty`。确认时重新读取目录，价格或可出售量发生变化时返回最新目录，避免按旧预览结算。

UI-5 后续可直接使用上述目录与结算接口接入买卖窗口、数量选择和样式；本次不新增窗口、布局或素材。所有结算仍应调用逻辑接口，保留开关、预览重验与事务 ID 约定。
