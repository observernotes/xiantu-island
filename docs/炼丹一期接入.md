# 炼丹一期接入（backlog #8）

沿用原有地图对象、材料合并物品表、任务目标定义、HUD 切片和主角外观系统，补采集、丹炉窗口、火候与炼丹结算。未改共享或快照 balance JSON。

## 读取的配置与素材

- 地图：`type=gather`、对象名/坐标、`props.item`；丹炉兼容 `type=furnace/alchemy`、`props.furnace/item`。已有地图未放丹炉，孙郎中提供公共青铜炉；获得丹炉后可用 L 打开。
- `materials.json`：`id/name/icon/kind`、`gather.castMs/respawnMs`。材料表负责时长/冷却，地图的同名冷却不覆盖材料表；实际地图对象负责点位，`gather.maps` 和动画 note 的旧中文占位不限制现有点。
- `recipes.json`：`id/name/type/output/outputCount/recipeLevel/baseRate/materials[].item/count/fuelStones`；`rules.perAlchemyLevel/levelGapPenalty/minRate/maxRate/furnace`；`rules.fire.skipped/inZone/perfect/missed/zoneWidth/perfectWidth/periodMs/zoneRandomPerBrew`；`rules.quality.base/perAlchemyLevelShift/perfectFireBonus/effectMul`；`rules.alchemyExp.perBrew/toNext/maxLevel`。`reqLevel` 按 G3 是购买等级，本轮没有商店。
- 任务：`rewards.recipes[]` 授方并去重；`objectives.craft.target/count` 只计接任务后成功产物数量。回春丹每炉按表产出 5 颗，craft 记 5。
- 主角：沿外观系统读取当前图集 `gather` 动画，没有时用 `idle`。采集点图集按 `anims` 播 idle/harvested；读取 `origin/hitArea/promptOffsetY`。
- UI：`hud_ui.json` 键帽 `size/nineSlice/text`；`alchemy_ui.json` 窗口布局、丹方行/按钮/火候框 `nineSlice/slice`、火候区/经验条 `threeSlice`；图鉴公共窗体 `bestiary_ui.json` 的切片。炉火图集 `meta.anim.key/frameRate/repeat`。采集框读取现有描述里的 slice 和 innerRect 数值，显示在角色 y−88。

## 缺字段、文案与兼容

- **火候 26%、4%、1200ms 已在表**；缺字段时分别按 design/06 兜底，当前没有触发这三个兜底。小游戏结束时间缺结构化字段，沿文档约 2 秒设 2000ms。
- `alchemyExp.perBrew/toNext` 仍是公式文字，解析 `×10` 与 `50×`；解析失败兜底 10/50。品质升级偏移未给高三品分配比例，暂按其基础权重 30:9:1 分摊；正中品质加成从下品转移，保持概率总和 1。
- `alchemy_ui.gather.castbar` 只有描述字符串，缺独立结构化采集 slice/innerRect 记录，当前直接解析表中的数字。美术 README 的 y−80、正中线 3%、约 2 秒往返示意服从本任务 y−88 和已定稿数值。
- 孙郎中 `npcs.quests` 缺 `q_alchemy_intro`，只为该任务补代码兼容入口；不派生开放其他未接任务。新手对白脚本没有该任务，使用 06 教学台词和原料/交付说明兜底。
- 入门任务把丹方和丹炉放在交付奖励，交付又要求先炼丹。接取时先教回春丹试炼，孙郎中公共炉可用；交付按原奖励授方去重。表内 collect 是交付持有 3 草，炼制另耗 2 草/1 绒/10 石，实际需备 5 草；不擅改任务表。
- 窗口附加标签、材料/燃料不足、批量统计、空丹方、公共炉提示和教学解释缺 strings key，暂用中文兜底；已有 `alchemy.*`、品质、`gather.*`、任务接取/完成 key 继续读表。
