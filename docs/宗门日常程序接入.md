# 宗门日常程序接入（v0.5）

依据根目录 `design/01_配置表规范.md` 的 G2、G8 后「宗门贡献来源」，读取共享 `balance/quests.json`、`npcs.json`、`strings_zh.json` 与 `solo_pacing.json`；没有修改配置表或 `data/` 快照。

## 字段与发布条件

- 任务读取 `id/daily/sect/phase/giver/turnIn/reqLevel/prereq/reqRealm/next`、`nameKey/descriptionKey/dialogueKeys.{offer,progress,complete}`、`objectives[].{type,target,count,consume}`、`balanceTodo`；`objectives[].map` 保留为配置中的地点元数据，当前地点提示来自任务描述文案。
- 奖励读取 `rewards.{exp,spiritStone,sectContribution,items,skills,recipes}`；物品与功法沿已有领取接口，未另设奖励途径。
- 接引人读取 `id/name/map/sprite/dialog/quests/phase`。日常只向已拜入对应宗门的角色开放，本宗接引人菜单显示本宗固定三条，普通任务继续使用原流程；已完成项当日灰显。头顶 `! / ? / …` 使用普通任务原有标记与素材。
- 贡献缺字段时才读取 `solo_pacing.sectSeclusion.dailyQuestContribution`；显式 `0` 有效，`null`、负数、非整数或无效回退值禁用该条日常。`balanceTodo` 非空、修为或灵石奖励未定稿也禁用。当前十五条 `balanceTodo: []`，修为、灵石、贡献均已配齐，实际贡献优先使用每条任务配置。
- `objectives[].map` 仍为目标地点指引；击杀不增加地图强约束，收集按背包持有量检查，交付时依据 `consume` 扣料。

## 重置、存档与去重

日常使用运行端本地日历的 05:00：05:00 前属于前一天，05:00 起属于当天。换日清空所有 `daily: true` 的任务状态和目标进度，包括已完成任务与未交付任务；背包材料保留，普通任务保留。不累计离线额度。

存档新增 `dailyQuestResetDay`（上次处理的日常日期）、`dailyQuestCompletions`（各宗当日已交付任务 id）；沿用并改接 `sectDailyContributionDay/sectDailyContributionClaims` 为同一 05:00 日界的贡献收据。读档、接取、交付、目标事件与任务状态查询校验跨日，场景每秒额外刷新。每条每日最多交付一次、每宗每日最多三条。

`QuestSystem.turnIn` 在交付前重验当天状态、正式宗门、目标、配置与领取记录，再同步扣料、记完成、发修为/灵石/物品/功法/配方、通过 `gainSectContribution` 发贡献，随后保存完整结果。它返回奖励回执，`GameScene.giveRewards` 对日常只显示回执日志；没有回执时直接返回。旧 `onSectDailyQuestCompleted` 与新交付共用同一领取判定，不能额外追加默认贡献。

沿用原有 `Progress.save` 的 localStorage 保存能力及失败处理，没有新增存储失败回滚保证。闭关仍调用已有 `spendSectContribution`，闭关每日年数上限继续按原来的本地午夜划分，日常 05:00 不改变闭关日界。

## 文案与地图缺口

十五条日常的名称、描述、接取、进行中、交付共 **75 个专用文案 key 全部存在**。接取/完成/进度/可交付提示复用 `quest.accept/quest.complete/quest.progress/quest.complete_ready`；修为、灵石、物品、功法使用 `sys.exp_gain/sys.stone_gain/sys.item_gain/skill.learned`；贡献提示使用现有 `sect.ui.contribution` 显示领取后的余额；菜单标题和对白操作提示使用 `ui.quests/ui.dialog.accept/ui.dialog.next/ui.dialog.close`。

专用「日常已重置」「今日日常次数已用完」「宗门贡献 +n」缺少 key。本次不新增硬编码提示：重置后菜单和标记自动恢复，当日完成项复用 `quest.complete` 灰显，贡献使用已有余额文案。任务目标标签直接读取怪物/物品/NPC 名称，再放入 `quest.progress`；无需新增击杀、收集、对话标签。配置未开放复用 `sect.ui.config_pending`。

天剑宗 `tianjian_envoy_sect` 已登记但山门地图没有点位；程序在天剑山门出生点右侧 96 像素（`spawn.x + 96, spawn.y`，当前坐标 `224,832`）补同 id 接引人，后续地图配置有该 id 时自动停止补点。四宗 `taixu_temple/lingfu_pavilion/youying_tower/wanshou_mountain` 山门地图尚缺；程序仅对已拜入该宗的玩家在落霞镇同样相对出生点的坐标（当前 `224,640`）补本宗同 id 接引人，不开放其他宗门日常。此兼容不改 NPC 原地图登记，不补试炼点位或新航线；地图/点位配齐后应撤下安全区兼容入口。补出的接引人使用正常 NPC 对话、交付和头顶标记流程。

船老大航线菜单现在也记录 `talk` 任务目标，幽影宗「渡口听风」可正常完成问讯。
