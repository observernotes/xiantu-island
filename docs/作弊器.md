# 本地内部作弊器

供内部调试与验收使用。启动时 URL 含 `cheat=1` 或 `cheat=true` 才启用；`cheat=0`、缺少参数或其他值都不会启用，也不会挂载 `window.__cheat` 或面板。

**默认直接修改当前存档**：资源、等级、任务、技能、道袍、物品等操作复用当前 `Progress`，经 `Progress.save()` 写入浏览器当前站点的 localStorage `xiantu_save_v1`。不是临时角色，也没有独立作弊存档。使用前可在开发者工具中备份该键；去掉 `cheat` 参数只会关闭作弊入口，不会回滚已经保存的修改。无敌状态及刷出的临时怪物不作为角色存档保存。

## URL 参数

除已有 `map`、`debug` 等游戏参数外，下表的作弊参数都要求先启用 `cheat`。启动阶段只应用一次；切图继续保留面板和本次运行的无敌状态，不重复赠送资源或物品。

| 参数 | 示例 | 行为 |
|---|---|---|
| `cheat` | `cheat=1` / `cheat=true` | 启用作弊器。 |
| `god` | `god=1` | 开启无敌；玩家受击直接返回，不扣血、不进入受伤状态。 |
| `stone` | `stone=12345` / `stone=` | 将灵石 `prog.stones` 设为指定值；参数出现但未填值时为 `999999`。不传则不改。 |
| `contrib` | `contrib=12345` / `contrib=` | 将宗门贡献 `prog.sectContribution` 设为指定值；未填值时为 `999999`。不传则不改。 |
| `realm` | `realm=炼气` / `realm=foundation` | 按境界名称或 ID 匹配；中文可省略末尾「期」。设置到该境界起始等级，同步境界奖励并回满气血、灵力。 |
| `level` | `level=29` | 直接设置等级，限制在当前配表 `1..MAX_LEVEL`，同步境界奖励并回满气血、灵力。 |
| `exp` | `exp=满` | 将当前修为设为当前等级的 `expNeed`，便于验证满修与突破。 |
| `map` | `map=qingyun_village` | 沿用 `GameScene` 启动读取的地图参数，可与作弊参数叠加。面板/API 可在运行中传送到已注册地图及 `field_test`。 |
| `quest` | `quest=accept:q_bamboo` | 经 `QuestSystem.accept` 接取；常规条件不满足时，作弊入口可强制设为 active 并保存。 |
| `quest` | `quest=complete:q_bamboo` | 自动接取、补齐目标，再经 `turnIn` 交付和发奖；已经 done 的任务跳过，不重复发奖。 |
| `quest` | `quest=skip` | 对操作当时全部 active 的非日常任务逐一执行完成路径。 |
| `spawn` | `spawn=mon:demon_fox` | 在玩家附近生成一只已登记怪物，死亡后不重生；不会改地图配表。 |
| `spawn` | `spawn=item:fox_tail` / `spawn=item:fox_tailx5` | 调用 `addItem` 将物品加入背包并保存；省略数量时为 1。 |
| `unlock` | `unlock=skills,outfits` | 逗号列表可只填一项；`skills` 授予全部登记技能，至少 1 级，并填入快捷栏空位；`outfits` 补齐五宗道袍，已有的不重复发放。 |

`quest`、`spawn` 可重复传入，例如 `quest=accept:q_bamboo&quest=complete:q_bamboo&spawn=mon:spirit_rabbit&spawn=item:fox_tailx3`。非法 ID 或不合法输入会输出提示，不应导致游戏崩溃。

日常任务交付仍遵守所属宗门、功能开关和每日次数限制；`quest=skip` 只处理非日常任务。

境界 ID 与当前起始等级：`mortal`（凡人，1）、`qi_refining`（炼气期，10）、`foundation`（筑基期，30）、`golden_core`（金丹期，60）。中文 URL 可直接粘贴到浏览器，浏览器会处理编码。

## 启动示例

本地启动：

```sh
npm install
npm run dev
```

基础组合，无敌、灵石、贡献、炼气境界和全部解锁：

```text
http://localhost:5173/?cheat=1&god=1&stone=&contrib=&realm=炼气&unlock=skills,outfits
```

满修验突破，并指定出生地图和调试参数：

```text
http://localhost:5173/?cheat=true&level=29&exp=满&map=qingyun_village&debug=timing
```

任务与刷怪、刷物：

```text
http://localhost:5173/?cheat=1&quest=complete:q_bamboo&spawn=mon:demon_fox&spawn=item:fox_tailx5&map=bamboo_forest
```

Pages 示例（将账号、仓库路径换成实际部署路径）：

```text
https://<账号>.github.io/<仓库>/?cheat=1&god=1&map=qingyun_village&spawn=mon:spirit_rabbit
```

同一浏览器中，本地 Vite 与 Pages 属于不同站点，使用各自的 localStorage；同一站点下的不同路径通常共用该存档键。不要为了关闭作弊器而加 `reset=1`，该参数会按游戏原有逻辑重置存档。

## 面板与控制台

启用后屏幕角落出现小面板；按反引号键（`` ` ``）或 `F2` 开关。面板提供无敌切换、灵石/贡献设置、升境/满修、按 ID 接取或完成任务、刷怪/刷物、解锁技能/道袍以及常见地图传送。面板修改与 URL 操作使用同一套逻辑，涉及角色数据时同样保存当前存档。

场景就绪后可在控制台使用：

```js
const c = window.__cheat;
c.enabled;                       // 仅 cheat 启用时挂载
c.god;                           // 当前无敌状态
c.setGod(true);
c.setStones(999999);
c.setContrib(999999);
c.setRealm('筑基');
c.setLevel(29);
c.fillExp();
c.acceptQuest('q_bamboo');
c.completeQuest('q_bamboo');
c.skipQuests();
c.spawnMon('demon_fox');
c.spawnItem('fox_tail', 5);
c.unlockSkills();
c.unlockOutfits();
c.nextRealm();
c.teleport('qingyun_village');     // 返回是否发起传送，完成切图后再操作
```

传送返回布尔值，表示是否已发起切图；切图完成后再执行其他操作。切图后 API 操作当前场景，面板与无敌状态继续保留。

全部技能的跨职业使用资格只在本次作弊运行中生效，该资格开关不写入存档。强制完成外宗拜入任务会保存任务奖励，但保留已有职业；使用外宗奖励技能需再解锁全部技能。离开作弊模式后恢复正常职业限制，正常读档迁移也可能清理外宗技能；道袍加入背包后仍以正常模式的穿戴条件为准。

## 正式构建与验证

正式 Pages 默认 URL/入口页不添加 `cheat` 参数。作弊器通过启动 URL 门控动态加载，不依赖 `VITE_XT_TEST`；正式构建手动添加参数也可启用，但默认启动完全关闭。此功能不改发版默认入口、数值 JSON 或现有 crashGuard。

`?map=`、`?debug=` 仍按各自原有逻辑工作；作弊器可与测试构建的 `window.__xt` 叠加。`__xt` 是否存在仍由原有 `VITE_XT_TEST` 规则决定，添加 `cheat` 不会绕过该构建开关，`?__xt` 也不会自行启用作弊。

本地检查：

1. 执行 `npm run build`（包含 `tsc --noEmit`）、`npm run test:cheat` 和 `npm run test:smoke:cheat`；浏览器冒烟需要本机 Playwright 与 Chromium，可通过 `PLAYWRIGHT_MODULE` / `CHROMIUM_EXECUTABLE_PATH` 指定路径。
2. 不带 `cheat` 打开游戏：无作弊面板，`window.__cheat` 为 `undefined`；单独 `?god=1&stone=` 不能启用作弊。
3. 打开基础组合 URL，确认面板出现、资源/境界生效、玩家受击不掉血；用 `F2` 与反引号键验证开关。
4. 验证接取/完成任务、刷怪/刷物、解锁与切图；同一已完成任务再次完成不重复奖励。
5. 去掉 `cheat` 并刷新，确认无敌与面板关闭，已保存的资源、背包和任务仍保留。
